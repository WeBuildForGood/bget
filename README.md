# Build For Good — Build. Grow. Evolve. Together.

The public website for **Build For Good**, a global, multidisciplinary community
for turning meaningful problems into collective action.

> Bring us a problem. We'll bring together the people who can help.

Production: **Cloudflare Workers** — https://buildforgood.nikhilnagpure203.workers.dev

(The old `bget` Worker is being retired in favour of the rebranded Build For Good site.)

---

## 1. Stack

| Layer | Choice |
| --- | --- |
| Framework | Next.js 16 (App Router), **static export** (`output: 'export'`) |
| Language | TypeScript |
| UI | React 19, Tailwind v4 + design tokens (`app/globals.css`), lucide-react |
| Hosting | Cloudflare Workers static assets (`wrangler.toml` → `[assets]`) |
| API | `worker/index.js` — JSON API for public forms, plus optional SSR for public project pages |
| Database | Cloudflare D1 (`buildforgood-forms`), schema in `migrations/` |

The Next app is fully static. All server logic lives in the Worker, which serves
the export through the `ASSETS` binding and handles `/api/*` (and can render
selected dynamic routes like `/projects/:slug` from D1).

## 4. API

### Public
| Method | Route | Body | Stores in |
| --- | --- | --- | --- |
| `GET` | `/api/health` | — | — |
| `POST` | `/api/apply` | name, email, building, ... | `applications` |
| `POST` | `/api/problems` | title, description, visibility, ... | `problems` |
| `POST` | `/api/contact` | name, email, subject, message | `contact_messages` |
| `POST` | `/api/suggestions` | topic, body, name?, email? | `suggestions` |
| `POST` | `/api/feedback` | kind, page?, body, email?, rating? | `feedback` |
| `POST` | `/api/projects` | title, one_liner, description, lead_name, ... | `projects` (status `pending`) |
| `GET` | `/api/projects` | — (query optional) | returns approved projects (JSON) |
| `GET` | `/api/projects/:slug` | — | returns approved project (JSON) |

### Admin (Cloudflare Access)
| Method | Route | Purpose |
| --- | --- | --- |
| `GET` | `/api/admin/me` | Authenticated email |
| `GET` | `/api/admin/summary` | Counts by type/status |
| `GET` | `/api/admin/:collection` | List (applications, problems, projects, contact_messages, suggestions, feedback) |
| `PATCH` | `/api/admin/:collection/:id` | Update `{ status, notes }` |
| `POST` | `/api/admin/projects/:id/approve` | Approve project (or PATCH status `approved`) |
| `DELETE` | `/api/admin/:collection/:id` | Soft/hard delete as configured |

All POST routes validate input, ignore a hidden honeypot field, return `{ ok: true, id }`, and respond `405` to non-POST. Admin routes require a valid Cloudflare Access JWT for `buildforgood.nikhilnagpure203.workers.dev`.

## 7. Deployment

Push to `main` → GitHub Actions:
1. `.github/workflows/ci.yml` (job **`test`**) — `npm ci` + `npm run build`
2. `.github/workflows/deploy.yml` — rebuilds the static export and runs
   `npx wrangler deploy` (uploads `out/` assets + `worker/index.js`)

Branch protection requires the status check literally named **`test`**.

Manual deploy:
```bash
export CLOUDFLARE_ACCOUNT_ID=87fd5601199078add1a9f9f88d3608d6
npm run build
npm run deploy         # wrangler deploy
```

Required GitHub secret: `CF_API_TOKEN` (Workers Scripts + D1 edit).

### Staging
- Push to `staging` branch or label a PR `preview`.
- `.github/workflows/deploy.yml` deploys to `--env staging`.
- URL pattern: `https://buildforgood-staging.nikhilnagpure203.workers.dev`

### Preview (PR deploy)
- Every pull request triggers `deploy-preview` job.
- Command: `wrangler deploy --env preview`
- Preview URL is posted as a PR comment automatically.
- Preview includes health-check verification (`/api/health` must return 200).

### Security
- See `SECURITY.md` for reporting and policies.
- CI runs `npm audit --audit-level=moderate`, `npm outdated`, and Trivy scan.
- `cloudflaretoken.env` is ignored by `.gitignore`; never commit secrets.
- `wrangler.toml` contains only names/IDs — no keys.
- Admin routes (`/api/admin/*`, `/admin`) protected by Cloudflare Access.

### Rollback steps
1. Identify last good commit tag or branch point.
2. `git checkout <good-commit>`
3. `npm run build && npx wrangler deploy --env production`
4. Verify with `curl -f https://buildforgood.nikhilnagpure203.workers.dev/api/health`
5. If health fails, redeploy previous version via `wrangler deploy --env production --tag <previous>`.

## 8. Cloudflare Access (Admin)

The `/admin` panel and `/api/admin/*` endpoints are protected by Cloudflare
Access (Zero Trust). Access validates the JWT and passes it as
`Cf-Access-Jwt-Assertion`; the Worker verifies the token against your Access
team's JWKS and enforces the policy audience. The authenticated email is
available as `Cf-Access-Authenticated-User-Email` (and from the verified JWT).

Configuration steps (in Cloudflare Zero Trust dashboard):
1. Create an **Access application** for `buildforgood.nikhilnagpure203.workers.dev` (path include `/admin/*`, `/api/admin/*` or protect the entire hostname as appropriate).
2. Create an **Access policy** allowing only approved admin emails/domains.
3. Note the **team domain** (e.g. `your-team.cloudflareaccess.com`) and the
   **application's Audience (AUD)** or policy; set these as Worker secrets/env
   (`ACCESS_TEAM_DOMAIN`, `ACCESS_AUD`) if implementing strict JWT validation.
   The Worker includes a reference implementation in `worker/access.js`.

Until Access is fully configured for the new workers.dev hostname, `/api/admin/*`
returns 401 if the JWT is missing/invalid. This is expected and safe.
